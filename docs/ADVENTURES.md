# مغامرات الستريك

## المراجعة قبل التنفيذ

المشروع يستخدم aiogram وSQLite، وهو مرتبط بـ `business_connection_id + chat_id`.
التفعيل صريح: صاحب الحساب يبدأ، أو يوافق على طلب الطرف الثاني. رسائل الحالة
والإحياء والأوامر الإدارية لا تُحتسب كنشاط. بعد التفعيل يطبق نوع المحتوى المختار،
ثم يسجل الرسالة ويكمل اليوم مرة واحدة داخل `BEGIN IMMEDIATE`، وبعد الحفظ يرسل
الملصق عبر وضع الضيف أو المسار البديل الحالي. الإحياء يحتاج موافقة الطرفين
ويستهلك حماية، والحماية التلقائية تمر عبر المجدول. إعادة ربط حساب الأعمال تنقل
البيانات إلى معرف الاتصال الجديد.

مراجعة `main` عند `d5f9a7b` وجدت 56 اختبارًا ناجحًا و7 إخفاقات سابقة:
اختبارات قديمة ناقصة معاملات وضع الستريك/هوية المالك، اختبار حفظ لم يفعل
المحادثة، وصيغة «إحياء» غير موجودة في محلل أمر الاختبار. تم تحديث الاختبارات
وتصحيح الصيغة، دون تغيير شروط التفعيل.

## مراحل التنفيذ

1. جداول مستقلة وحفظ ذري لـ shared_xp وshared_level والمهام والمقارنة.
2. Combo وأحداث متباعدة وإنجازات ظاهرة وسرية.
3. ربط صفحات غنية وبديل نصي، واحتفال بداية عبر وضع الضيف.
4. صورة ستوري عمودية بصور وأسماء الطرفين، مع فيديو متحرك اختياري.
5. اختبارات الهجرة والتكرار والتزامن وإعادة الربط والواجهات والفيديو الحقيقي.

## السلوك

- مستوى واحد للطرفين. المستوى الأول يحتاج 100 XP، والثاني 200 إضافية، وهكذا.
- مهمتان يوميتان، والثالثة فقط عند ظهور المهمة النادرة. المكافآت 10–40 XP
  حسب المهمة؛ إكمال الجميع يعطي 20 إضافية، وإكمال اليوم الحقيقي يعطي 20.
- الصور والفيديو والبصمات والنصوص تستطيع تحقيق مهمة، لكن اكتمال يوم الستريك
  يبقى مشروطًا بوضع المحتوى المختار. الأوامر الإدارية وزر الحالة لا تعطي XP.
- المقارنة تبدأ من تفعيل التحديث، ولا تُختلق إحصاءات للأيام القديمة. تحصي
  المبادرة، أيام المشاركة، أول مشاركة بعد 22:00، والإحياء المشترك.
  النسبة تقريبية: 10 نقاط مساهمة لكل يوم مشاركة، مع نقاط المهام والمكافآت؛
  المكافآت الثنائية توزع بالتساوي. تكرار الرسائل لا يزيد النسبة.
- الإحياء يُنسب للطرفين، والحماية التلقائية تظهر كإنقاذ مشترك مستقل.
- إكمال اليوم قبل 22:00 يرفع Combo إذا كان اليوم السابق جيدًا. التأخير، يوم
  فائت، حماية تلقائية، إحياء أو تصفير الستريك تصفر Combo فقط. XP والإنجازات تبقى.
- مكافأة Combo هي 5 × min(combo, 5)، حتى لا تصبح المكافآت غير محدودة.
- فرصة حدث 20% في الأيام المؤهلة، مع يومين عاديين على الأقل بعد كل حدث.
  الحدث النادر يمثل 3% من الأحداث، أو 8% عند Combo ≥ 5. بقية الأحداث:
  XP مضاعف، حماية مجانية، مكافأة Combo، يوم سريع ويوم هدوء.
- الحماية المجانية تُمنح فقط عند إكمال اليوم وتبقى ضمن الحد الحالي 3؛ إذا
  الرصيد كامل يحصل الفريق على XP بدلها. لا تُفعّل الحماية التلقائية بنفسها.
- بعض الإنجازات مخفية حتى فتحها، وبعدها يظهر اسمها وسبب الحصول عليها.
- إشعارات المكافآت مجمعة عند إكمال اليوم/كل المهام، بحد أقصى إشعارين باليوم.
  التفاصيل تتحدث مباشرة داخل صفحة المهام. إعداد كتم التنبيهات يحترم الإضافات.
- احتفال Jake بلا رقم عند أول اكتمال طبيعي لستريك جديد (الوصول إلى يوم 1)،
  وليس عند فتح الحالة أو الإحياء أو إضافة أيام يدويًا. له حارس دائم ضد التكرار
  بنفس اليوم. الملصق الاحتفالي مستقل عن مزامنة الحزم الحالية.

## الملفات والحفظ

- `app/adventures/rules.py`: القواعد والحسابات فقط.
- `app/adventures/views.py`: النصوص والصفحات والأزرار.
- `app/database/adventure_repository.py`: إنشاء الجداول وعمليات الحفظ.
- `app/services/adventure_service.py`: توصيل الاحتفال والمكافآت وخدمة الستوري.
- `app/handlers/adventures.py`: تحقق هوية الطرفين والتصفح واختيار مدة الفيديو.
- `app/story/renderer.py`: تركيب الإطارات وتشكيل العربية واللحن وترميز MP4.

`adventure_profiles` يحفظ shared_xp وshared_level، وحالة Combo والإحصاءات
والإنجازات وتاريخ بداية التتبع، إضافة إلى توقيت آخر طلب فيديو.
`adventure_days` يحفظ المهام والحدث وأوقات أول مشاركة والمهام المنجزة والمكافآت
وحراس الإشعارات لكل يوم محلي. النصوص والصور الواردة لا تحفظ؛ يحتفظ باسم العرض
وإحصاءات نوع المحتوى فقط. جداول الإضافات تنتقل مع إعادة ربط الاتصال.

إنشاء الجداول إضافي وقابل للتكرار. مكافأة النشاط وتحديث اليوم وحارس تكرار
الرسالة داخل معاملة SQLite نفسها. خطأ قبل commit يعيد المعاملة كاملة.
تغيير وضع الستريك يصفر توقيت مشاركة اليوم غير المكتمل، دون مسح المهام/XP
أو السماح بتكرار عداد المشاركة. الأيام اليدوية لا تعطي مكافآت لعب.
كل يوم محفوظ بتاريخ توقيت الاتصال. إعادة فتح الصفحة لا تعيد اختيار المهام.
لا تُمنح مكافآت ليوم أقدم من أحدث يوم معروف أو لتحديث رسالة مؤرخ بيوم سابق.

## مشاركة الستوري

من زر «مشاركة ستوري» يقدر أحد الطرفين يختار **صورة ستوري** مباشرة، وهي PNG
عمودية 720×1280 فيها صور الطرفين وأسماؤهم داخل كرتين وJake يلعب بيهن، مع
نص الستريك وعدد الأيام. إذا ما متوفرة صورة لأحد الطرفين يظهر أول حرف من اسمه.

ويبقى كخيار إضافي فيديو **5 أو 10 ثواني**، عمودي 720×1280 و24fps، H.264 + AAC،
مع faststart وحركة Jake والكرات والموسيقى. الصورة أو الفيديو ينرسلون في محادثة
الستريك عبر اتصال الأعمال، ويمكن حفظهم ومشاركتهم كستوري؛
لا ينشر ستوري تلقائيًا على حساب أي طرف. الاحتفال والمكافآت يدعمان وضع الضيف.
أزرار الملصق تفتح رسالة جديدة إذا تعذر تحويل رسالة الملصق إلى صفحة نصية.

صور الملفات الشخصية وصورة/فيديو الستوري ملفات مؤقتة تحذف بعد الإرسال. لا تُرسل الصور إلى خدمة توليد
خارجية. التوليد في عامل منفصل عن حلقة البوت؛ حد أقصى عمليتان متزامنتان
وطلب واحد للمحادثة كل 60 ثانية. FFmpeg له مهلة ترميز 90 ثانية.

لم تحدد أغنية، لذلك يوجد لحن احتفالي أصلي مدمج. لاختيار أغنية ضع ملف الصوت
على الخادم واضبط `STORY_MUSIC_PATH=/path/to/song.mp3`. لا حاجة لإضافة مكتبة
توليد صور أو حساب خارجي. صورة الستوري تعتمد Pillow مع RAQM، والفيديو يعتمد FFmpeg وPillow مع RAQM وخط
DejaVu Sans Bold. Docker وCI يثبتان متطلبات النظام. خارج Docker:

```bash
sudo apt-get update
sudo apt-get install -y ffmpeg fonts-dejavu-core libraqm0
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

عند فشل الصورة، يُستخدم البديل. عند فشل التوليد، تظهر رسالة واضحة ويمكن
إعادة المحاولة بعد دقيقة، دون تعديل الستريك أو XP.

## التحقق والتجربة

الاختبارات تغطي الحفاظ على الستريك بعد الهجرة، منع تكرار المكافآت، تزامن
التحديثات، rollback وإعادة المحاولة، إغلاق/فتح قاعدة البيانات وإعادة ربط
الاتصال، أحداث الحماية وحدها الحالي، المقارنة والمهام وتغيير الوضع وكسر
Combo والإحياء وكتم التنبيهات، منع وصول طرف ثالث، والبديل النصي للرسائل الغنية.
اختبارات الفيديو ترمز فعلًا نسختي 5 و10 ثواني وتتحقق بـ ffprobe من الصوت
والأبعاد والمدة، وتقارن الإطارات للتحقق من الحركة.

بعد النشر: افتح «ستريك» ← «مهام ومستوى» أو «مقارنة ودية»، واختبر الستوري
بالمدتين. اختبارات API تستخدم بدائل Telegram؛ إرسال الرسائل الغنية/وضع الضيف
والفيديو إلى حساب Telegram حي يحتاج تجربة بعد النشر. العدادات محفوظة قبل
الإرسال؛ فشل الشبكة لا يرجع XP ولا يعيد منحه، لكنه قد يمنع وصول إشعار المكافأة.
